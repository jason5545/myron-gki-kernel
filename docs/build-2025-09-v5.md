# v5：修正 6.12.38 面板無法點亮

v4 實機測試時，顯示 HAL 每次 atomic commit 都被 `drm_atomic_check_valid_clones()` 以 `-EINVAL` 拒絕，面板從未點亮，經過見 [v4 驗收](build-2025-09-v4.md)。這項檢查是 6.12.23 到 6.12.38 之間上游新增的，原廠 SDE 驅動的 encoder `possible_clones` 不符合它的假設。

`0006-drm-log-instead-of-reject-invalid-clones.patch` 只改這一處：條件不符時用 `pr_warn_once` 記錄 CRTC、`encoder_mask`、encoder 與 `possible_clones`，不再回傳 `-EINVAL`。函式是 static，不影響 KMI。其他內容與 v4 相同：2025-09 基底（6.12.38、KMI 5）、ReSukiSU v4.2.0-rc3、SUSFS v2.3.0、LK v1.8.1 的三項設定、`rust_binder.ko` 例外。

## v6：版本字串改為 `-g<commit>`

v5 以前的版本字串是 `-maybe-dirty`。這不是刻意的選擇，是 Kleaf 的預設：`build/kernel/kleaf/impl/stamp.bzl` 在沒有 `--config=stamp` 時固定填 `-maybe-dirty`，避免每次讀取 git 狀態。

`scripts/build.sh` 改成：先把 patch 與 root 來源在 `common` 內提交成 commit（作者固定，日期沿用基底 commit，同樣的輸入會得到同樣的 sha），再以 `--config=stamp` 編譯。v6（專案 commit `fa34dce`，Image `f7f98cc9140b…`）的橫幅：

```
原廠：Linux version 6.12.23-android16-5-g16e473de48a3-abogki462654244-4k (kleaf@build-host) … #1 SMP PREEMPT Wed Nov 19 12:38:00 UTC 2025
v6  ：Linux version 6.12.38-android16-5-ga4b2f18ca52a-4k (kleaf@build-host) … #1 SMP PREEMPT Tue Sep 29 01:49:39 UTC 2026
```

`ga4b2f18ca52a` 是實際的 commit，父節點是官方基底 `1ad7be92`。原廠的 `-abogki…` 是 Google 建置伺服器的 build ID，這裡不是官方建置，不加。CRC 與 v5 相同；v6 尚未做手機暫存重封裝驗收，也還沒刷入。

## v7：commit 開頭固定為 `4b4d4935`

依 Jason 的想法，版本字串的 commit 開頭固定為 `4b4d4935`，也就是 "KMI5" 的 ASCII 十六進位。git 雜湊只有十六進位字元，base64（`S01JNQ==`）放不進去。

`scripts/vanity_commit.c` 在 patch commit 的訊息尾端加一行 `vanity-nonce`，找出讓 SHA-1 以指定前綴開頭的最小 nonce；結果是真實存在的 git commit，執行緒數不同也得到同一個 nonce。`build.sh` 預設啟用（`SCM_PREFIX=` 可關閉），9950X3D 上 8 碼前綴約數十秒。

## v8：取自參考核心的 UFS 修正（2026/10/2）

Jason 定方向：只做最佳化、維持小米官方行為，UFS 可以加。上游 linux-6.12.y 從 6.12.38 到 6.12.111 之間的 UFS 改動都是修正，沒有真正的效能最佳化；效能相關的時脈、auto-hibern8、WriteBooster 策略在高通 `ufs-qcom` vendor 模組，GKI 不能改。因此直接採用參考核心已做的 UFS 改動：

| patch | 來源 | 內容 |
| --- | --- | --- |
| `0007-ufs-runtime-pm-error-recovery.patch` | LunaKernel OS3 分支 | 錯誤處理遇到進行中的 runtime PM 時改走鏈路復原，避免死鎖；6.12.38 的 `ufshcd_err_handler` 仍缺這段 |
| `0008-ufs-rtc-work-serror-during-suspend.patch` | linux-6.12.y stable `2fcc2fc21` | 修 UFS suspend 時 RTC work 觸發的 SError |

LunaKernel 主分支的 `0267a9417`（Cancel RTC work in active-active suspend）修的 active-active suspend 分支在 6.12.38 不存在，未採用。
